### 2026-09-04: Preserve real brand logos and typography roles in generated tools
**By:** Backend
**What:** Tool generation now preserves real Context.dev logo assets and font roles more faithfully. Canonical logo normalization accepts inline data-URI logos (so Context.dev SVG wordmarks are not discarded), brand parsing keeps fallback favicon/og-image links plus component-level font families when top-level typography is sparse, and the generation snapshot/prompt now passes heading/body font roles with a larger 32k inline-logo budget. When no logo is available, the prompt explicitly requires plain text branding only and forbids invented icons or badges.
**Why:** The Airbnb and Mailchimp investigations showed Context.dev was returning usable brand assets; the fidelity failures were downstream toolbuilder bugs, not an upstream data absence. Mailchimp's real logo was being dropped from the prompt because its canonical PNG data URI exceeded the old 18k cap, and both domains were vulnerable to placeholder icon invention whenever the model lacked or ignored a concrete logo instruction. Passing the real asset more often, retaining inline-logo candidates, and making the fallback honest removes the fabricated-icon failure mode while improving UI-font fidelity for brands that expose separate display and body faces.
