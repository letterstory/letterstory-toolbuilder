### 2026-09-05: 16-brand production fidelity sweep confirms logo fix but exposes widespread font stripping
**By:** Tester
**What:** I ran fresh production `/api/tools/generate` checks across 16 brands and saved full JSON plus header/style evidence under `artifacts/brand-fidelity-sweep/`. Logo fidelity passed 16/16, color fidelity passed 15/16, but font fidelity passed only 1/16 (Chase). The dominant remaining issue is that most generated tools end up on generic `-apple-system/BlinkMacSystemFont/.../sans-serif` stacks even when `brandSnapshot` names a specific brand font. DoorDash also dropped its secondary color `#EC9C84` from CSS.
**Why:** Sweep evidence shows deterministic logo injection is now working, but font fidelity is still broadly broken. The likely root cause is in `src/lib/generation/brand-enforcement.ts:216-229,247-279,337-354,486-492`: when a brand font is not embedded, `buildRolePlan()` returns a pure system stack and `rewriteFontFamilies()` rewrites every CSS `font-family` declaration to that fallback, erasing the brand family names entirely. This matched 15 brands including Stripe, Notion, Slack, Figma, Linear, Nike, Target, Etsy, DoorDash, American Express, Spotify, Netflix, NYT, and Vogue. Separately, the live API still requires `projectName`, producing initial 400s (`src/lib/surfaces/tools.ts:207-219`), and the live rate limit is 10 generate requests per 600 seconds (`src/lib/rate-limit/rules.ts:15-18`), which constrains large sweeps.
