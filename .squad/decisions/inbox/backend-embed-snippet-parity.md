### 2026-09-05: Server surfaces now return embed snippets for tool generate/get
**By:** Backend
**What:** Added additive `embedSnippet` support to generated-tool detail and generate responses across REST, MCP, and CLI. The server now builds the snippet from the shared iframe contract (`buildEmbedSnippet`) and derives origin from the incoming request using forwarded headers when present (`x-forwarded-proto`, `x-forwarded-host`, `x-forwarded-port`, plus `Forwarded`/`Host` fallback), with `TOOLBUILDER_BASE_URL` as an env fallback and `http://localhost:3000` as the final dev default. CLI `tools get` / `tools generate` now prints a labeled embed snippet section and can synthesize the snippet from its configured base URL if a server response is missing the field.
**Why:** `buildEmbedSnippet()` previously lived only in the dashboard workspace, so generate/get parity across REST/MCP/CLI was incomplete even though the embed contract already existed. Centralizing snippet generation on the server closes that gap without changing the sandbox/security posture or the list-summary payload shape. I deliberately left `generatedToolSummarySchema` / list responses unchanged to avoid bloating the recent-tools/list surface with repeated snippets that callers can already fetch from detail/generate. Validation passed: `npm test`, `npm run typecheck`, `npm run build`, and `npm run parity:check`.
