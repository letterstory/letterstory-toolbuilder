### 2026-09-04: Dashboard routes must opt out of Next full-route static caching
**By:** Infra
**What:** The `(dashboard)` app-router segment now exports `dynamic = "force-dynamic"` and `revalidate = 0` so `/brand`, `/build`, and future dashboard pages are served dynamically instead of as prerendered static HTML with a one-year `s-maxage`. No Porter persistent cache volume was found; the stale deploy behavior came from cacheable static dashboard responses that could survive redeploys in upstream/shared caches.
**Why:** `/brand` had been auto-static because its page/layout only rendered client shells, so `next build` emitted `.next/server/app/brand.html` and served `x-nextjs-prerender: 1` plus `cache-control: s-maxage=31536000`. That let an old HTML shell keep referencing a pre-cutover JS chunk (`page-86d72c31ab5beb77.js` containing `Running Firecrawl ingestion`) even after later deploys. During remediation, Porter also got stuck mid-rollout because the cluster could not schedule a surge pod alongside the old one, so the live app had to be cycled through `instances: 0 -> 1` on the current image tag to actually replace the stale pod. For live tooling dashboards, serving fresh HTML with no long-lived full-route cache is safer than relying on cache invalidation behavior outside the app.
