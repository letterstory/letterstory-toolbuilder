### 2026-09-06: Tool-logic classifier failures now fail open, and Anthropic network fetches retry once
**By:** Backend
**What:** I wrapped `prepareToolLogic()`'s initial `classifyToolLogicRequirement()` call in a local `try/catch` so classifier errors now return the existing `fallback` result shape instead of crashing the whole generate/revise request. I also added a shared internal retry in `requestAnthropicText()` that retries exactly once, after a short jittered 200–400ms delay, when `fetch()` throws a non-`AbortError` network-layer failure before any response arrives.
**Why:** Staging 500s were traced to transient outbound network failures during the pre-build Anthropic classifier call. That call previously had no protection, so a single DNS/reset/TLS blip escaped through `prepareToolLogic()` and failed the entire request. The local fail-open fix closes the direct bug; the shared retry reduces recurrence for the classifier and every other Anthropic-backed step without changing the public request/response interface or the separate HTML-generation retry system. Validation target: targeted unit tests for both paths plus `npx tsc --noEmit` and the full Vitest suite.
