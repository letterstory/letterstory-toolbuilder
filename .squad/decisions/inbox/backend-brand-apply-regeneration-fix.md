# 2026-09-06
**By:** Backend

**What:** Fixed the Brand snapshot Apply regression by sending explicit `brandOverrides` from the dashboard to `/api/tools/generate`, merging those overrides into the authoritative revision-time `brandSnapshot` on the server before model invocation, persisting the merged snapshot on the updated tool record, and preserving manually selected fonts in CSS as `named_with_fallback` stacks when no self-hostable font metadata exists. Also removed the workspace's client-side brand-snapshot overlay so the UI now reflects the server's real saved result instead of masking persistence failures.

**Why:** Root cause was general to the revision path, not rollback-specific: brand-edit requests only changed the free-text prompt, while `reviseTool()` kept reusing the old stored `brandSnapshot` as the authoritative brand context whenever `siteUrl` stayed the same. That meant the Anthropic revision prompt still told the model to use the old colors/fonts, and the updated record kept persisting the old snapshot. Rollback made the bug easy to reproduce because it re-exposed an older snapshot/version pair, but the same failure also happened on non-rollback brand edits. A second coupled issue made diagnosis harder: the workspace optimistically overlaid the edited colors/font onto the visible summary even when the backend had not actually saved them. Finally, brand enforcement was stripping manually requested font-family names when there was no embedded font-face metadata, so even a successful manual font override could disappear from stored HTML.
