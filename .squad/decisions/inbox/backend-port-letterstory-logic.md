### 2026-09-05: Port letterstory's mode-aware logo + font-face normalization into toolbuilder
**By:** Backend
**What:** Toolbuilder's Context.dev normalization now preserves every returned logo variant with mode/type/dimensions/colors, picks the active logo mode-aware while avoiding `has_opaque_background` assets when possible, and keeps structured font-face metadata (`google`, `category`, `files`, `fallbacks`) on the normalized `BrandProfile`. I kept the existing top-level `primaryLogoUrl`, `logoUrls`, `fonts`, and typography string fields for backward compatibility, and only extended the profile with optional richer fields.
**Why:** Lead explicitly wanted the good local logic from letterstory PR #1350 without introducing a direct runtime dependency on letterstory's org-scoped API. I intentionally deferred custom-font self-hosting/embedding for generated tools: the current generator contract forbids remote font URLs, and safely inlining/rehosting arbitrary font binaries would be a larger rendering/storage change than this port. Preserving `fontLinks` metadata now closes the data-model gap immediately and gives us the right inputs for a later self-hosting step if typography fidelity still needs that investment.
