### 2026-09-05: Restore serif-safe fallbacks without regressing sans-serif brands
**By:** Backend
**What:** I removed the body-driven `brandPrefersSansFallback` heading scrub in `src/lib/generation/brand-enforcement.ts` and replaced it with conservative per-role fallback classification. Non-embedded fonts now fall back to serif only when the authoritative font family name is confidently serif (for example Times New Roman / Garamond-family names or names containing `serif` but not `sans-serif`); otherwise they default to the existing system sans stack. I also stopped the post-rewrite unloadable-family text replacement that was duplicating system stacks, and I now emit deterministic CSS custom properties for primary/secondary/accent/background/text tokens so DoorDash's secondary `#EC9C84` survives in generated CSS.
**Why:** The previous Mailchimp fix (`306cb5d`) over-corrected by using `detectSansFallbackPreference()` to coerce any serif heading fallback back to sans whenever the body/UI font was sans. That preserved Mailchimp, but it erased legitimate editorial serif headings for brands like NYT and Vogue. The extra unloadable-family replacement pass also re-replaced safe web fonts such as Arial inside the already-rewritten stack, which caused duplicated `-apple-system ... Arial, sans-serif` sequences in DoorDash output. Fresh live verification after deploy `7d55f40` shows the intended split now: NYT `bb2a9f76-0252-4747-b19d-135a8c334fdb` includes `font-family: "Iowan Old Style", Georgia, Cambria, "Times New Roman", Times, serif !important;`, Vogue `b035a7bf-d0fc-49b3-805d-4c29894d292e` includes both serif fallback lines and the same serif `!important` enforcement line, Mailchimp `2c5b8025-0022-443f-80a4-d62239ba9a18` stays on `font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif !important;`, and DoorDash `7bcfb8e7-6bf7-4a98-b073-58a078f488cc` keeps sans fallback while now exposing `--ls-brand-color-secondary: #EC9C84;` plus live usage at `.metric-tile .mt-value.warn { color: #EC9C84; }`.
