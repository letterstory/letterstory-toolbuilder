### 2026-09-06: Editable brand snapshot uses revision-driven rebuilds
**By:** Frontend
**What:** Made the dashboard’s Brand snapshot panel editable with a lightweight inline edit mode: native color inputs plus paired hex fields for captured colors, a curated font select (`Inter`, `Poppins`, `Roboto`, `Lato`, `Merriweather`, `Playfair Display`, `system-ui`) with custom-font fallback behavior, and an Apply button that submits through the existing `/api/tools/generate` revision flow instead of instant iframe retheming. The Apply handler now composes a scoped natural-language update prompt from only the changed fields and reuses the same in-flight/loading/success/error UX as chat revisions. Frontend also overlays successful brand edits back onto the visible tool snapshot for the active version so the dashboard immediately reflects the user’s requested colors/font even though the backend still stores the original ingestion snapshot on same-site revisions.
**Why:** Phase 1’s requirement is “real regeneration, not CSS-var patching,” so the safest integration point is the existing update pipeline. The inline controls keep the panel visually close to the current dashboard card design, the prompt builder keeps revisions narrow (“change only these brand tokens; keep layout/functionality the same”), and the client-side snapshot overlay avoids a confusing post-regeneration mismatch where the preview changed but the dashboard still showed the old extracted brand values.
