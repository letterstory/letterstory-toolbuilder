### 2026-09-05: Revision retries now get a larger in-request Anthropic budget
**By:** Backend
**What:** I kept the overall `/api/tools/generate` request target budget at 280s, but split the retry timeout by path: fresh generations still retry at 35s, while in-place revisions now get up to 70s on their retry attempt. I also documented the initial-vs-revision budget math in `src/lib/generation/orchestrator.ts` and added regressions covering revision retry budgeting plus rollback restoring a prior version while preserving newer history.
**Why:** The live failure was not caused by nginx. Revision already skips brand re-fetch when the URL is unchanged and reserves no advisory budget up front, but it still reused the same 35s retry cap as fresh generation. In the real failing run, attempt 1 returned invalid/incomplete HTML after ~152.6s, leaving the second attempt only the hard-coded 35s budget (`x-tool-generation-attempts: 1:invalid_html:152650/210000|2:timeout:35002/35000`), which is too short for a full revision pass because revision prompts include the existing HTML and are materially heavier than scratch prompts. The fix gives revisions the remaining headroom they actually need while still staying under the app's 280s target and the live 300s ingress ceiling. Validation: `npm test`, `npm run typecheck`, and `npm run build` all passed.
